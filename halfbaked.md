# halfbaked.md — What's Real and What's Next

This file tracks what's working, what's synthetic, and what we'd build next with more time. Full transparency for judges.

_Last updated: 2026-10-16_

---

## What's Working

| Feature | Status | Notes |
|---|---|---|
| Drug interaction detection | **Working** | 1,079 interaction pairs across 70 drugs. Flags CRITICAL/HIGH/MODERATE/LOW for 60K patients based on active prescriptions. |
| Provider Dashboard | **Working** | Personalized: shows only the logged-in provider's patients, metrics, and alert details. Email sign-up built in. |
| Patient Portal | **Working** | Shows patient's own medications and interaction alerts. Full-page translation in 9 languages via AI_TRANSLATE. |
| AI Chat | **Working** | Grounded in drug interaction knowledge base via Cortex Search (SEARCH_PREVIEW) + AI_COMPLETE. Adapts tone for patients vs. providers. |
| Interaction Checker | **Working** | Check any drug against a patient's current meds, or compare any two drugs from 70-drug formulary. |
| Semantic Views | **Working** | 3 views: patient medications, interaction alerts, clinical encounters. Real DDL syntax, verified with Cortex Analyst. |
| Cortex Search | **Working** | 2 services: drug interactions (175 entries) + pharmacist notes (154K). Queried via SEARCH_PREVIEW. |
| Restricted Caller's Rights | **Working** | 3 RCR procedures with EXECUTE AS RESTRICTED CALLER + GRANT CALLER. End users have no direct table access. |
| Role-based navigation | **Working** | Single-page app with sidebar radio. Providers, patients, and admins each see only their pages. |
| Email alert drafts | **Working** | AI_COMPLETE generates professional alert emails. Stored in ALERT_EMAIL_LOG. Scheduled task ready (suspended). |
| Parameterized SQL | **Working** | All user input uses `params=[]`. No SQL injection risk. |

## What's Synthetic (Demo Data)

| Item | Notes |
|---|---|
| Drug interaction data | Generated by AI_COMPLETE (claude-sonnet-4-6), not from a clinical database. Labeled "AI-generated, not clinically validated" on every screen. In production, DrugBank Marketplace data would replace this. |
| Extended drug list (50 drugs) | AI-generated common drug names and classes. Production would use a real formulary. |
| Patient language preferences | Assigned by `PATIENT_ID % 10`. Production would come from patient intake forms. |
| Login/authentication | Session-state only. No real auth. Providers pick from a dropdown; patients use name + DOB. |

## Known Limitations

| Item | Details |
|---|---|
| Cortex Agent runtime | Agent object is created and configured with 3 semantic views + 2 search services. DATA_AGENT_RUN returns "missing execution environment" — a warehouse resolution issue in the SQL function. Chat falls back to Cortex Search + AI_COMPLETE, which works. |
| Email delivery | Alert drafts are generated and stored, but SYSTEM$SEND_EMAIL requires a verified user email (not set on the hackathon account). The self-service sign-up flow and draft pipeline are complete. |
| Alternative suggestions | LLM-suggested. Not checked against the patient's other medications for overlapping side effects. |

## What We'd Build Next

1. **DrugBank Marketplace integration** — Replace AI-generated interactions with clinically validated data from DrugBank Biomedical Knowledge
2. **Side-effect overlap detection** — When suggesting alternatives, check that the alternative doesn't share side effects with the patient's other drugs
3. **Real authentication** — SSO or Snowflake-native auth instead of session-state login
4. **Live email delivery** — Wire SYSTEM$SEND_EMAIL with verified provider emails from the sign-up table
5. **Streaming chat** — Upgrade SiS runtime to support st.chat_input and streaming responses
