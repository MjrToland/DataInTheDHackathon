# halfbaked.md — What's Faked, Partial, or Not Yet Working

This file tracks every shortcut, stand-in and known gap in the project, so judges can see exactly what is real.
Status key: **FAKE** = invented or simulated data · **PARTIAL** = real but limited scope · **BROKEN** = written but won't run as-is · **NOT RUN** = never executed or verified · **NOT DONE** = planned, not built

_Last updated: 2026-10-16_

---

## 1. Source data

| Item | Status | Details |
|---|---|---|
| All of `HEALTHCARE_DW`, `FINSERV_DW`, `AUTO_MFG_DW` | FAKE | Sample datasets supplied by the hackathon. They're synthetic, not real patients. |
| Medication list (20 drugs) | PARTIAL | `PHARMACY.MEDICATIONS` has exactly 20 drugs. That's the whole table, but a real formulary has thousands. Every interaction, alert and alternative is limited to these 20. |
| Prescriptions (154K rows) | FAKE | Synthetic. `PHARMACIST_NOTES` come from a small set of repeated templates. |
| Prescription status | PARTIAL | A query for `STATUS = 'ACTIVE'` returned **0 rows**. The samples show `FILLED`. Our "currently taking" logic counts `FILLED` as active, which is an assumption. The real meaning of each status hasn't been checked yet. |
| Cross-database patient overlap (~90%) | FAKE (artifact) | The overlap almost certainly comes from the synthetic data generator reusing names, not from a real shared population. The match is on first name + last name + state only, with no real identifier. |
| Warranty claims text | FAKE | Templated verbatims, and `COMPLAINT_DESCRIPTION` is often mismatched with `SYSTEM_AFFECTED`. No accident or injury language exists, so the auto-to-healthcare link found nothing. |

## 2. Drug interaction knowledge

| Item | Status | Details |
|---|---|---|
| `DRUG_INTERACTIONS` table | FAKE | Generated by `AI_COMPLETE` (an LLM) for the 190 pairs of the 20 drugs. Not clinically validated. Severity, mechanism, management and alternatives are all LLM output. |
| Alternative drug suggestions | FAKE | LLM-suggested. They aren't checked against the formulary, so an alternative may not be one of our 20 drugs. They aren't checked for side-effect overlap with the patient's other drugs either, even though the goal says they should be. |
| DrugBank Biomedical Knowledge (`GZTYZJ6Q7W0`) | NOT DONE | Not installed. The listing needs a "Request" approved by DrugBank before full data is available. The trial may be a subset. |
| FDA FAERS adverse events (`GZ2FWZ5FDDY`) | NOT DONE | Not installed (7-day trial). Coverage is 2018 Q1 – 2021 Q1 only. |
| Mapping our drugs to Marketplace IDs | NOT DONE | No NDC → DrugBank/RxNorm crosswalk built yet. `01_marketplace_install.sql` also uses guessed database names. |
| Side-effect overlap detection | NOT DONE | A core idea (recommend alternatives without overlapping side effects) isn't built. It needs DrugBank Adverse Effects or FAERS reactions data. |
| Dose / frequency awareness | NOT DONE | Interactions ignore dosage, so the same pair counts as the same risk at any dose. |

## 3. Patient & provider attributes

| Item | Status | Details |
|---|---|---|
| `PREFERRED_LANGUAGE` | FAKE | Doesn't exist in the source. `02_data_enrichment.sql` adds it to `CORE.PATIENTS` and assigns a language by `PATIENT_ID % 10`. **It also changes the source table.** It should move to a separate preferences table. |
| Provider email addresses | FAKE / NOT DONE | `CORE.PROVIDERS` has no email column. Real delivery needs a provider → email mapping, which will be made up for the demo. |
| Provider and patient login | FAKE | There's no authentication. Users pick a provider from a dropdown, or "log in" as a patient with last name + DOB. Anyone can view anyone's record, so this is not a real "personalized view". |

## 4. Snowflake features (judging criteria)

| Criteria | Status | Details |
|---|---|---|
| Streamlit | NOT RUN | 4 pages written, never deployed or run. |
| Cortex Agents | BROKEN | `05_cortex_agent.sql` uses made-up syntax. The chat page calls plain `AI_COMPLETE` with no data access, so it **doesn't use the agent**. Its answers aren't grounded in our data. |
| Semantic Views | BROKEN | `03_semantic_views.sql` uses made-up syntax. It needs the real `TABLES / RELATIONSHIPS / DIMENSIONS / METRICS` form. |
| Cortex Search | NOT RUN | Syntax is plausible but unverified. It depends on the `DRUG_INTERACTIONS` table existing first. |
| AI_TRANSLATE | PARTIAL | The code calls `SNOWFLAKE.CORTEX.TRANSLATE`, not the newer `AI_TRANSLATE` function the criteria name. Translations are made on the fly and not cached. Drug names and alternatives aren't translated. |
| Restricted Caller's Rights | BROKEN (mislabelled) | Procedures use `EXECUTE AS OWNER`, which is **owner's rights, not RCR**. They must be rewritten with `EXECUTE AS RESTRICTED CALLER` plus caller grants. |

## 5. Email pipeline

| Item | Status | Details |
|---|---|---|
| Email sending | FAKE | Emails are AI-drafted and **written to `ALERT_EMAIL_LOG` only**. Nothing is sent. Needs an email notification integration + `SYSTEM$SEND_EMAIL`, and recipients must be verified Snowflake user emails. |
| "As they appear" detection | PARTIAL | The task runs every 6 hours over the full alert view, not on new prescriptions. A stream on `PRESCRIPTIONS` would make it event-driven. Since the data is static, no "new" interactions will ever appear without seeding test rows. |
| Scheduled task | NOT RUN | Uses the `COMPUTE_WH` warehouse (existence not confirmed). The task is resumed in the script, so it would start using credits as soon as it's deployed. |
