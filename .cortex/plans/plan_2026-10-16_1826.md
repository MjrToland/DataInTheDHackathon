## Context

Currently the app has no login -- providers pick from a dropdown, patients enter last name + DOB. There's no landing page that differentiates the two roles. The email pipeline logs drafts but never sends because there are no verified emails. The `PROVIDER_CONTACTS` table has fake `@metro-health.demo` addresses.

## Plan

### 1. New table: `DDI_APP.PROVIDER_EMAIL_SUBSCRIPTIONS`

Replace the static `PROVIDER_CONTACTS` table with a subscription table that providers populate themselves:

```
PROVIDER_ID  NUMBER PK
EMAIL        VARCHAR  -- entered by the provider
SUBSCRIBED   BOOLEAN DEFAULT TRUE
SUBSCRIBED_AT TIMESTAMP_NTZ
```

### 2. Rewrite `app.py` as a login/role-selection landing page

The front page becomes a "Who are you?" screen with two cards:

- **I'm a Provider** -- type-ahead search by name from `CORE.PROVIDERS` (active only). Selecting a provider stores `provider_id` and `role=provider` in `st.session_state` and shows sidebar nav to Provider Dashboard, Chat, and Inbox Triage.
- **I'm a Patient** -- last name + DOB lookup (existing flow). Stores `patient_id` and `role=patient` in session state and shows sidebar nav to Patient Portal and Chat.
- A **"View as Admin"** option that skips login and shows all pages (for the demo/judges).

Once "logged in," the sidebar shows the user's name and a logout button. All pages read from `st.session_state` instead of re-asking who the user is.

### 3. Add email sign-up to `provider_dashboard.py`

At the top of the provider dashboard, after the provider is identified from session state:

- Check `PROVIDER_EMAIL_SUBSCRIPTIONS` for their `PROVIDER_ID`.
- If no row: show a banner "Sign up for email alerts" with a text input for email + a Subscribe button. On click, INSERT into the subscriptions table.
- If subscribed: show "Alerts will be sent to you@example.com" with an Unsubscribe button.

### 4. Update `inbox_triage.py` to show subscription status

In the Statistics tab, add a small "Email Subscriptions" section showing how many providers are subscribed.

### 5. Update all other pages to use session state

- `provider_dashboard.py`: read `provider_id` from `st.session_state` instead of the dropdown. Keep a fallback dropdown for admin mode.
- `patient_portal.py`: read `patient_id` from `st.session_state` instead of asking for name+DOB. Keep fallback for admin mode.
- `chat.py`: show patient or provider context in the prompt based on who's logged in.

### 6. DDL changes

- `CREATE TABLE DDI_APP.PROVIDER_EMAIL_SUBSCRIPTIONS`
- `DROP TABLE DDI_APP.PROVIDER_CONTACTS` (replaced)

### 7. Update `halfbaked.md`

Note the email pivot and the new login page.
